# Decisiones de Fases 3 y 4

- **Escáner:** `qr-scanner` ejecuta el reconocimiento en un Worker, usa `BarcodeDetector` si está disponible y carga su motor de respaldo; expone detección y control de linterna opcional. `BarcodeDetector` por sí solo no tiene disponibilidad general; `html5-qrcode` documenta torch, pero su repositorio informa mantenimiento pausado. La búsqueda manual y los lectores USB/Bluetooth como teclado siguen disponibles. Fuentes: [qr-scanner (Nimiq)](https://github.com/nimiq/qr-scanner), [Barcode Detection API (MDN)](https://developer.mozilla.org/en-US/docs/Web/API/Barcode_Detection_API), [html5-qrcode (proyecto)](https://github.com/mebjas/html5-qrcode).
- **Offline:** la aplicación precachea el shell con Workbox y mantiene catálogo y cola en Dexie. Envía movimientos secuencialmente en orden de inserción de IndexedDB (no usa hora del teléfono para ordenar); el servidor asigna `fecha_servidor` UTC que define el orden oficial. Cada registro conserva su UUID y delta. Sincroniza al iniciar, al evento online, con intervalo de 15 s y botón manual. Fallos permanecen visibles en la cola.
- **Dashboard:** polling autenticado cada 5 s. Para una LAN y pocos operadores evita reconexiones/eventos perdidos y hace el flujo de operación más fácil de observar; no se requiere latencia subsegundo.
